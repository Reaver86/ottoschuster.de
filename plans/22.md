# Zahlungslink für eine vorausgefüllte Überweisung per WhatsApp

Stand: 12. September 2026

## Fragestellung

Gibt es eine Möglichkeit, einen Link mit IBAN, Empfängername, Betrag und
Verwendungszweck zu erzeugen, sodass der Empfänger ihn in WhatsApp anklicken
und die vorausgefüllte Überweisung nur noch bestätigen muss?

## Kurzantwort

Einen universellen Link, der auf jedem Smartphone die jeweils installierte
deutsche Banking-App mit einer vorausgefüllten SEPA-Überweisung öffnet, gibt es
derzeit nicht. Eine Zahlung darf außerdem nicht allein durch das Öffnen eines
Links ausgeführt werden: Der Zahler muss die Angaben prüfen und die Überweisung
autorisieren.

Für private Zahlungen ist Wero momentan die bequemste Lösung, sofern beide
Teilnehmer Wero aktiviert haben. Ohne Wero ist ein EPC-QR-Code (GiroCode) plus
lesbar mitgeschickte Zahlungsdaten die kompatibelste Lösung. Für geschäftliche
Zahlungen kommen Zahlungslinks eines Payment- oder Open-Banking-Anbieters
infrage.

## Möglichkeit 1: `payto:`-URI

RFC 8905 definiert ein standardisiertes URI-Schema für Zahlungsziele. Eine
SEPA-Überweisung kann beispielsweise so beschrieben werden:

```text
payto://iban/DE123...?receiver-name=Max%20Mustermann&amount=EUR:25.00&message=Rechnung%20123
```

Unterstützte Angaben sind unter anderem:

- IBAN
- Empfängername (`receiver-name`)
- Betrag und Währung (`amount`)
- unstrukturierter Verwendungszweck (`message`, bei SEPA maximal 140 Zeichen)
- End-to-End-Referenz (`instruction`, maximal 35 Zeichen)

### Einschränkungen

- WhatsApp erkennt `payto:` nicht als anklickbaren Weblink und stellt die URI
  deshalb nur als Text dar.
- Das Betriebssystem kann eine `payto:`-URI nur öffnen, wenn eine installierte
  App das Schema als Handler registriert hat.
- Bei den üblichen deutschen Banking-Apps ist diese Unterstützung derzeit
  nicht verlässlich dokumentiert oder flächendeckend vorhanden.
- Auch bei vorhandener Unterstützung muss der Nutzer die Zahlungsdaten prüfen
  und die Zahlung bestätigen.

### HTTPS-Brücke als Test

Die fehlende Anklickbarkeit in WhatsApp lässt sich mit einer normalen
HTTPS-Zwischenseite umgehen. In WhatsApp wird dann beispielsweise dieser Link
verschickt:

```text
https://ottoschuster.de/pay/abc123
```

Die Zielseite enthält einen Button mit der eigentlichen `payto:`-URI:

```html
<a href="payto://iban/DE123...?receiver-name=Max%20Mustermann&amp;amount=EUR:25.00&amp;message=Rechnung%20123">
  In Banking-App öffnen
</a>
```

Der Ablauf wäre:

1. Der Empfänger tippt in WhatsApp auf den HTTPS-Link.
2. Die Zwischenseite öffnet sich und zeigt Empfänger, IBAN, Betrag und
   Verwendungszweck zur Kontrolle an.
3. Der Empfänger tippt auf „In Banking-App öffnen“.
4. Falls eine installierte App `payto:` unterstützt, öffnet das Betriebssystem
   diese App beziehungsweise eine App-Auswahl.
5. Ohne registrierten Handler erscheint eine Fehlermeldung oder es passiert
   nichts.

Eine automatische Weiterleitung von der HTTPS-Seite auf `payto:` kann
zusätzlich versucht werden. Browser und insbesondere In-App-Browser können sie
jedoch blockieren. Ein sichtbarer Button sollte deshalb immer als Fallback
vorhanden sein.

Die HTTPS-Brücke löst lediglich das WhatsApp-Problem. Sie kann eine Banking-App
nicht dazu bringen, `payto:` zu unterstützen. Für einen praktischen Test könnte
die Seite zusätzlich einen EPC-GiroCode und kopierbare Zahlungsdaten als
Fallback anzeigen.

## Möglichkeit 2: EPC-QR-Code / GiroCode

Der standardisierte EPC-QR-Code kann Empfängername, IBAN, Betrag und
Verwendungszweck enthalten. Eine unterstützende Banking-App liest den Code und
füllt damit die Überweisungsmaske aus; der Nutzer autorisiert die Zahlung
anschließend selbst.

Der QR-Code kann als Bild per WhatsApp verschickt werden. Auf demselben
Smartphone funktioniert das allerdings nur bequem, wenn die Banking-App auch
einen QR-Code aus der Galerie beziehungsweise aus einer Datei importieren kann.
Die Unterstützung ist für Banken optional und daher nicht überall gleich.

Empfehlung: Neben dem QR-Code Empfängername, IBAN, Betrag und Verwendungszweck
immer noch einmal lesbar mitsenden.

## Möglichkeit 3: Wero

Mit Wero lassen sich Beträge von anderen Wero-Teilnehmern anfordern. Die
Telefonnummer, E-Mail-Adresse oder ein Wero-QR-Code dient als Kennung; die IBAN
bleibt im Hintergrund. Der Empfänger bekommt die Zahlungsanforderung, prüft sie
und bestätigt die Echtzeitüberweisung per Face ID, Fingerabdruck oder PIN.

Voraussetzung ist, dass beide Seiten Wero aktiviert haben und ihre Bank
teilnimmt. Eine Wero-Zahlungsanforderung ist kein universeller, frei erzeugbarer
IBAN-Link für beliebige Banking-Apps.

## Möglichkeit 4: Zahlungsdienstleister / Open Banking

Für geschäftliche Zahlungen können Payment-Service-Provider einen anklickbaren
HTTPS-Zahlungslink erzeugen. Nach dem Öffnen wählt der Kunde seine Bank, wird zu
deren Oberfläche weitergeleitet und autorisiert die bereits vorbereitete
Zahlung.

Das kommt dem gewünschten Ablauf am nächsten und ermöglicht üblicherweise auch
eine Zahlungsbestätigung sowie eine automatische Zuordnung. Dafür sind jedoch
ein Händlerkonto beziehungsweise eine technische Integration und meist
Transaktionsgebühren erforderlich.

## Empfehlung

- **Privat, beide nutzen Wero:** Wero-Zahlungsanforderung verwenden.
- **Privat, möglichst unabhängig von einem Anbieter:** EPC-GiroCode zusammen
  mit den Zahlungsdaten als Text verschicken.
- **Experiment:** Eine HTTPS-Zwischenseite mit `payto:`-Button, GiroCode und
  kopierbaren Zahlungsdaten bauen und mit verschiedenen Geräten und Banking-Apps
  testen.
- **Geschäftlich:** Einen Zahlungslink über einen Payment- beziehungsweise
  Open-Banking-Anbieter verwenden.
